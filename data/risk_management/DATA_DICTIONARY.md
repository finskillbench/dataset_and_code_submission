# Risk Management — Data Dictionary

Dataset for the Risk Management skill (V2a Skill 3). Contains daily prices, factor returns, macro indicators, covariance matrices, scenario portfolios with planted risk characteristics, investment mandates, stress scenarios, deterministic ground truth for 4 sub-tasks, and atomic task episodes for 30 S&P 500 tickers across 2018–2025.

Generated by `python -m scripts.risk_management.run_pipeline`.

## File Schemas

### Raw Data

#### `raw/factors/ff5_daily.csv` / `momentum_daily.csv`

Fama-French 5-factor + momentum daily returns from Ken French Data Library.

| Column | Type | Description |
|---|---|---|
| `date` | date | Trading date |
| `Mkt-RF` | float | Market excess return |
| `SMB` | float | Small minus big |
| `HML` | float | High minus low (value) |
| `RMW` | float | Robust minus weak (profitability) |
| `CMA` | float | Conservative minus aggressive (investment) |
| `RF` | float | Risk-free rate |
| `Mom` | float | Momentum factor (momentum file only) |

#### `raw/fred/{series}.json`

FRED macro series observations. Each file contains an array of `{"date", "value"}` records.

Series: `fed_funds_rate`, `treasury_10y`, `treasury_2y`, `cpi_yoy`, `unemployment`, `hy_spread`, `vix`, `usd_index`, `yield_curve_slope`.

### Processed Data

#### `processed/returns/daily_returns.parquet`

Wide-format daily simple returns. Columns are ticker symbols, index is trading date.

#### `processed/returns/log_returns.parquet`

Wide-format daily log returns. Same structure as `daily_returns.parquet`.

#### `processed/returns/rolling_volatility.parquet`

21-day rolling annualized volatility per ticker. Wide format.

#### `processed/returns/rolling_drawdown.parquet`

Running maximum drawdown per ticker from trailing peak. Wide format.

#### `processed/factor_exposures.parquet`

Rolling OLS factor betas (252-day window).

| Column | Type | Description |
|---|---|---|
| `date` | date | Estimation date |
| `symbol` | string | Ticker symbol |
| `mkt_rf` | float | Market beta |
| `smb` | float | Size beta |
| `hml` | float | Value beta |
| `rmw` | float | Profitability beta |
| `cma` | float | Investment beta |
| `mom` | float | Momentum beta |

#### `processed/factor_returns.parquet`

Cleaned daily factor return panel (FF5 + momentum), aligned to the price calendar.

#### `processed/macro_panel.parquet`

Merged macro indicator panel, forward-filled to daily frequency.

| Column | Type | Description |
|---|---|---|
| `date` | date | Trading date |
| `fed_funds_rate` | float | Federal funds effective rate (%) |
| `treasury_10y` | float | 10-year Treasury yield (%) |
| `treasury_2y` | float | 2-year Treasury yield (%) |
| `cpi_yoy` | float | CPI year-over-year change (%) |
| `unemployment` | float | Unemployment rate (%) |
| `hy_spread` | float | High-yield credit spread (bp) |
| `vix` | float | CBOE VIX index |
| `usd_index` | float | US Dollar index |
| `yield_curve_slope` | float | 10Y–2Y Treasury spread (%) |

#### `processed/covariance/cov_{YYYY-MM-DD}.npz`

Ledoit-Wolf shrinkage covariance matrix. NumPy compressed archive containing:
- `cov`: NxN annualized covariance matrix
- `symbols`: array of ticker symbols (row/column order)
- `date`: estimation date string

### Constructed Data

#### `constructed/portfolios/portfolio_{type}_{regime}_{index}.json`

Scenario portfolio with planted risk characteristics.

| Field | Type | Description |
|---|---|---|
| `portfolio_id` | string | Unique identifier |
| `portfolio_type` | string | One of: `concentrated`, `factor_tilted`, `liquidity_stressed`, `mandate_violating`, `stress_vulnerable` |
| `as_of_date` | string | Point-in-time date (YYYY-MM-DD) |
| `holdings` | array | Array of `{symbol, weight}` objects |
| `holdings[].symbol` | string | Ticker symbol |
| `holdings[].weight` | float | Portfolio weight (sums to ~1.0) |
| `planted_risks` | array | List of intentionally planted risk types (e.g. `sector_concentration`, `single_name_risk`, `low_diversification`) |
| `metadata` | object | Construction parameters (e.g. `target_sector`, `top_n_weight`, `num_holdings`) |

Portfolio types (5 × 40 = 200 total):
- `concentrated` — High single-name and sector concentration
- `factor_tilted` — Extreme factor exposures (value, momentum, etc.)
- `liquidity_stressed` — Overweight illiquid/small-cap names
- `mandate_violating` — Deliberately violates common mandate constraints
- `stress_vulnerable` — High sensitivity to specific stress scenarios

#### `constructed/mandates/mandate_{name}.json`

Investment mandate / constraint specification.

| Field | Type | Description |
|---|---|---|
| `mandate_id` | string | Unique identifier |
| `name` | string | Human-readable mandate name |
| `difficulty` | string | `easy`, `medium`, or `hard` |
| `benchmark` | string | Benchmark identifier (e.g. `SPY`) |
| `constraints` | array | Array of constraint objects |
| `constraints[].type` | string | Constraint type (see below) |
| `constraints[].value` | float/bool | Constraint threshold or flag |
| `constraints[].description` | string | Human-readable description |

Constraint types: `position_limit_max`, `position_limit_min`, `sector_limit_max`, `tracking_error_max`, `beta_range`, `long_only`, `min_names`, `max_turnover`.

12 mandates at 3 difficulty tiers: `simple_long_only`, `balanced_01`, `balanced_02`, `conservative`, `aggressive_growth`, `diversified`, `enhanced_index`, `institutional`, `quant`, `risk_parity`, `sector_neutral`, `tactical`.

#### `constructed/stress_scenarios/stress_{name}.json`

Stress scenario definition.

| Field | Type | Description |
|---|---|---|
| `scenario_id` | string | Unique identifier |
| `type` | string | `historical_replay` or `hypothetical` |
| `name` | string | Human-readable scenario name |
| `regime_slice` | string | Associated regime period |
| `replay_window` | object | `{start, end}` dates for historical scenarios |
| `description` | string | Narrative description |
| `market_shocks` | object | Shock magnitudes |
| `market_shocks.equity_drawdown_pct` | float | Equity market drawdown (%) |
| `market_shocks.vix_peak` | float | Peak VIX level |
| `market_shocks.credit_spread_widening_bp` | float | Credit spread widening (basis points) |
| `market_shocks.rate_change_bp` | float | Interest rate change (basis points) |

12 scenarios: 4 historical (`2018_selloff`, `covid_2020`, `2022_tightening`, `2023_24_reversal`) + 8 hypothetical (`equity_crash_20`, `rates_up_200`, `rates_down_100`, `credit_crisis`, `stagflation`, `strong_dollar`, `correlation_spike`, `sector_rotation`).

### Ground Truth

#### `ground_truth/risk_identification/gt_{portfolio_id}.json`

Sub-task 1: Identify and rank the top risk exposures in a portfolio.

| Field | Type | Description |
|---|---|---|
| `portfolio_id` | string | Reference to constructed portfolio |
| `as_of_date` | string | Point-in-time date |
| `risk_exposures` | array | Ranked list of risk exposures |
| `risk_exposures[].rank` | int | Risk rank (1 = highest) |
| `risk_exposures[].type` | string | Risk type: `factor_tilt`, `sector_concentration`, `single_name`, `concentration` |
| `risk_exposures[].detail` | string | Human-readable description |
| `risk_exposures[].magnitude` | float | Numeric magnitude of the exposure |
| `metrics` | object | Computed risk metrics |
| `metrics.var_95` | float | 95% daily Value-at-Risk (negative = loss) |
| `metrics.cvar_95` | float | 95% daily Conditional VaR |
| `metrics.hhi` | float | Herfindahl-Hirschman Index (concentration) |
| `metrics.top5_weight` | float | Sum of top 5 position weights |
| `metrics.effective_n` | float | Effective number of holdings (1/HHI) |
| `metrics.sector_exposures` | object | Sector → aggregate weight |
| `metrics.factor_exposures` | object | Factor → beta coefficient |

200 files (one per portfolio).

#### `ground_truth/constraint_monitoring/gt_{portfolio_id}_{mandate_id}.json`

Sub-task 2: Check portfolio compliance against a mandate's constraints.

| Field | Type | Description |
|---|---|---|
| `portfolio_id` | string | Reference to constructed portfolio |
| `mandate_id` | string | Reference to mandate specification |
| `as_of_date` | string | Point-in-time date |
| `constraints` | array | Per-constraint compliance results |
| `constraints[].type` | string | Constraint type |
| `constraints[].status` | string | `PASS` or `FAIL` |
| `constraints[].value` | float | Actual portfolio value for this constraint |
| `constraints[].limit` | float | Mandate limit |
| `constraints[].violation_magnitude` | float | Size of violation (only if `FAIL`) |
| `constraints[].worst_symbol` | string | Symbol causing worst violation (position constraints) |
| `constraints[].worst_sector` | string | Sector causing worst violation (sector constraints) |
| `overall_compliant` | bool | True if all constraints pass |
| `violations_count` | int | Number of failed constraints |

~600 files (portfolios × selected mandates).

#### `ground_truth/stress_testing/gt_{portfolio_id}_{scenario_id}.json`

Sub-task 3: Estimate portfolio P&L under a stress scenario.

| Field | Type | Description |
|---|---|---|
| `portfolio_id` | string | Reference to constructed portfolio |
| `scenario_id` | string | Reference to stress scenario |
| `as_of_date` | string | Point-in-time date |
| `estimated_pnl_pct` | float | Estimated portfolio P&L (negative = loss) |
| `attribution` | object | P&L attribution breakdown |
| `attribution.by_sector` | array | `{sector, contribution_pct}` per sector |
| `attribution.by_factor` | array | `{factor, contribution_pct}` per factor |

~2,400 files (portfolios × scenarios).

#### `ground_truth/risk_remediation/gt_{portfolio_id}_{mandate_id}.json`

Sub-task 4: Propose trades to bring a non-compliant portfolio back into compliance.

| Field | Type | Description |
|---|---|---|
| `portfolio_id` | string | Reference to constructed portfolio |
| `mandate_id` | string | Reference to mandate specification |
| `as_of_date` | string | Point-in-time date |
| `trades` | array | Proposed trade list |
| `trades[].symbol` | string | Ticker symbol |
| `trades[].action` | string | `buy` or `sell` |
| `trades[].current_weight` | float | Pre-trade weight |
| `trades[].target_weight` | float | Post-trade target weight |
| `trades[].trade_pct` | float | Trade size as % of portfolio (signed) |
| `total_turnover` | float | Total one-way turnover |
| `post_trade_compliant` | bool | Whether the remediated portfolio passes all constraints |
| `num_trades` | int | Number of trades proposed |

~400 files (non-compliant portfolio × mandate pairs).

### Episodes (Tasks)

Task JSONs live under `episodes/layer_a/{sub_task}/`. Each task bundles the input data references, an `as_of_date`, and a pointer to the corresponding ground truth file. 160 total tasks across 4 sub-tasks.

### Validation

#### `validation/summary.json`

11-check data quality validation report.

| Field | Type | Description |
|---|---|---|
| `run_date` | string | ISO timestamp |
| `universe_size` | int | Number of tickers |
| `checks` | object | Check name → `{status, ...}` |
| `overall_status` | string | Worst status across all checks |

Checks: `price_coverage`, `factor_data_quality`, `return_sanity`, `covariance_psd`, `factor_exposure_quality`, `portfolio_validity`, `ground_truth_consistency`, `point_in_time_leakage`, `task_coverage`, `macro_panel`, `stress_scenarios`.
